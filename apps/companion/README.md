# BiliMind

The whole study companion on your computer: courses, written lessons, Today, the planner, notes, whiteboards and your
own tasks, in a local database, with no account. The chat, lessons and essay marking run on your own DeepSeek or
OpenRouter key, called directly from this computer, and stop at limits you set in Settings; everything that doesn't
need a model works offline.

A course starts in the chat, as a draft you review. A lesson is written when you ask for it: the model says what kind
of knowledge it is, and the code decides which formats that kind must be taught in. "Build from a folder" runs the
older pipeline in its own process and brings the result in as an ordinary course, with the report of every answer
checked against your files.

```sh
pnpm install                                # from the repo root
pnpm --filter @bilimind/companion spa       # nuxt generate -> spa/
pnpm --filter @bilimind/companion build     # main + preload -> dist/
pnpm --filter @bilimind/companion start     # add --no-sandbox on Ubuntu 24.04+ in dev
pnpm --filter @bilimind/companion test      # the API and the planner
pnpm --filter @bilimind/companion e2e       # the app, headless, never on screen
pnpm --filter @bilimind/companion dist      # installers in release/ (--linux, --win, --mac; unsigned)
```

| Folder | What it is |
|---|---|
| `exported/` | The SPA and shell, copied one way from the hosted app. Don't edit: the next export overwrites it. |
| `overlay/` | What is different here, and the export never touches it. A file here wins over the same path in `exported/`. |
| `overlay/shell/src/api/` | The API the SPA speaks, in-process: `protocol.handle` on `app://bilimind/api/*`, no port, so nothing else on the computer can reach it. |
| `merged/` | The two together, generated by `scripts/merge.mjs`. Nuxt, esbuild and the tests read this. Not committed. |

Data lives in `companion.db` (SQLite through `node:sqlite`) and `files/` under the app's data folder. AI keys live in
`keys.json` beside them, sealed with Electron `safeStorage`. Where the system has no keychain (`basic_text` on Linux)
they stay plain in that 0600 file, and Settings says so. A key already in `~/.bilimind/config.json`, the file the CLI
shares, is copied in once and that file is left alone. Tests use a fake provider on localhost and never spend money.
