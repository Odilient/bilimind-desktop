Why order matters

A binary search tree keeps one promise: everything to the left of a node is smaller, everything to the right is larger. That single rule is why you can find a value by throwing away half of what is left at every step.

When the tree stays balanced, a search costs O(log n). When you insert sorted data, it degrades into a linked list and the cost becomes O(n).

  • Insert walks down from the root comparing as it goes.
  • Delete has three cases; the two-child case borrows the in-order successor.
Mentor note

Your lecturer asked about the two-child delete in both past papers. Practise it until it is boring.

Key terms
Root
The one node with no parent; every search starts here.
In-order successor
The smallest value in a node's right subtree.
Height
Edges on the longest root-to-leaf path.
Balanced
Left and right heights differ by at most one, everywhere.

function insert(root, value) {
  if (!root) return { value, left: null, right: null };
  // smaller goes left, the rest goes right
  if (value < root.value) root.left = insert(root.left, value);
  else root.right = insert(root.right, value);
  return root;
}
