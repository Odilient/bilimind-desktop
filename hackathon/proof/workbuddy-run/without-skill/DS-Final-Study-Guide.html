2. Algorithm Analysis, Arrays & Linked Lists 15 marks

Big O Notation — Formal Definition

f(n) = O(g(n))  iff  ∃ c > 0, n₀ ≥ 0  such that  |f(n)| ≤ c·g(n)  for all n ≥ n₀

This means g(n) is an upper bound on f's growth rate. In practice: drop constants and lower-order terms.

Example: 3n² + 5n + 2 = O(n²). Proof: for n ≥ 1, 3n² + 5n + 2 ≤ 3n² + 5n² + 2n² = 10n², so c = 10, n₀ = 1.

Exam tip: To prove f(n) = O(g(n)), you must give specific values of c and n₀ and show the inequality holds. Don't just say "drop the constants."

Analysing Loops — Rules

  • Sequential blocks add: O(n) + O(n²) = O(n²) (take the dominant term)
  • Nested loops multiply: n × n iterations → O(n²)
  • Doubling counter: i = 1, 2, 4, 8, … → log₂(n) iterations → O(log n)
Exam pattern: for (i=1; i<n; i*=2) for (j=0; j<n; j++) → outer loop O(log n) × inner loop O(n) = O(n log n)

Static Arrays

  • Contiguous memory block; access by index is O(1) (address = base + i × element_size)
  • Fixed capacity; insert/delete in middle shifts elements: O(n)
  • Good cache locality

Dynamic Arrays

  • Built on a fixed array plus a capacity; grows when full (commonly doubles)
  • Append is O(1) amortised: one append can cost O(n) (copy), but n appends copy at most 1+2+4+…+n/2 < n elements total, so total work = O(n), per-append = O(1) amortised
  • Growing by a constant amount (e.g., +10) gives O(n) per append on average — avoid this
  • Tripling instead of doubling: still O(1) amortised (geometric series argument)

Linked Lists

  • Nodes with value + next reference; singly, doubly, or circular
  • Insert/delete at a known node: O(1)
  • Access k-th element: O(n) (walk from head)
  • Deleting last node of a singly linked list: O(n) (need the node before it)

Reverse a linked list (past paper Q4b): Walk the list with three pointers (prev, curr, next). Reverse each link. Time: O(n), Space: O(1). 
function reverse(head) {
  let prev = null, curr = head;
  while (curr !== null) {
    let next = curr.next;   // save next
    curr.next = prev;       // reverse link
    prev = curr;            // advance
    curr = next;
  }
  return prev;              // new head
}

3. Hash Tables 30 marks

This is the biggest topic on the exam (30 marks). Spend extra time here. You must be able to trace insertions with linear probing AND chaining by hand.

The Dictionary (Map) ADT

Operations: insert(key, value), search(key), delete(key)

ImplementationSearchInsert

Sorted arrayO(log n)O(n)
Balanced BSTO(log n)O(log n)
Hash tableO(1) avgO(1) avg

How It Works

  • Array of m buckets; hash function maps key → index: index = hash(key) mod m
  • If every key gets its own bucket, search is a single array access
  • Collision: two different keys hash to the same bucket (unavoidable by pigeonhole principle)

Good Hash Function Properties

  • Deterministic: same key → same index, always
  • Uniform: spreads keys evenly across buckets
  • Fast to compute, uses the whole key
  • Division method: h(k) = k mod m (choose m prime, not close to power of 2)
  • Multiplication method: h(k) = ⌊m · (kA mod 1)⌋ with A ≈ (√5 − 1)/2 ≈ 0.618
  • Strings: polynomial hash h = h × 31 + code(c) for each character

Load Factor

α = n / m   (n = number of entries, m = number of buckets)
  • As α grows, collisions grow and operations slow down
  • Typical thresholds: 0.6–0.75 for open addressing; 1–3 for chaining
  • Java HashMap resizes at α > 0.75
  • Resize (rehash): allocate bigger table (double), re-insert every entry: O(n), but O(1) amortised per insert

Collision Resolution: Separate Chaining

  • Each bucket holds a linked list of entries that hash there
  • Insert: hash, add to chain: O(1)
  • Search/delete: hash, scan one chain: O(1 + α) expected
  • α may exceed 1 (chains get longer)
  • Worst case: all keys in one chain → O(n)
  • Deletion is simple (remove from list)

Collision Resolution: Open Addressing

  • Every entry stored in the bucket array itself; needs α ≤ 1
  • On collision, follow a probe sequence h(k, 0), h(k, 1), h(k, 2), … until empty slot
MethodProbe sequence
Linear probingh(k, i) = (h(k) + i) mod m
Quadratic probingh(k, i) = (h(k) + c₁i + c₂i²) mod m
Double hashingh(k, i) = (h₁(k) + i·h₂(k)) mod m, h₂(k) ≠ 0
Why h₂(k) must never be 0: If h₂(k) = 0, then h(k, i) = h₁(k) for all i — the probe sequence never leaves the home bucket, so every collision becomes a permanent failure.

Linear Probing — Worked Example

m = 10, h(k) = k mod 10. Insert: 89, 18, 49, 58, 69

89 → slot 9 (empty, 1 probe)    [_, _, _, _, _, _, _, _, _, 89]
18 → slot 8 (empty, 1 probe)    [_, _, _, _, _, _, _, _, 18, 89]
49 → slot 9 taken, try 0: empty  [49, _, _, _, _, _, _, _, 18, 89]   2 probes

Primary clustering: Linear probing creates contiguous runs of occupied slots. These runs grow and attract more collisions (any key that hashes into the run must scan through it). Double hashing reduces clustering because the probe step depends on the key, so different keys take different paths.

4. BST & AVL Trees 15 marks

Tree Vocabulary

  • Root: top node; Leaf: node with no children
  • Depth of a node: number of edges from the root
  • Height of a tree: number of edges on the longest root-to-leaf path
  • Binary tree: every node has at most 2 children (left, right)

The BST Property

For every node: all keys in the left subtree < node key < all keys in the right subtree

An in-order traversal visits keys in sorted order.

50 / \ 30 70 / \ / \ 20 40 60 80 Insert order: 50, 30, 70, 20, 40, 60, 80

BST Operations — all cost O(h), where h = height

  • Search: compare key with node; go left if smaller, right if larger; O(h)
  • Insert: search for the key, attach a new leaf where the search falls off; O(h)
  • Delete: three cases (see below); O(h)

Deleting from a BST — Three Cases

  1. Leaf: just remove it
  2. One child: replace the node by its child
  3. Two children: copy the in-order successor (smallest key in right subtree) into the node, then delete the successor (which has at most one child). The in-order predecessor (largest in left subtree) works too.
Example: Deleting 50 from the tree above: the in-order successor is 60 (smallest in right subtree). Put 60 at the root, then delete the original 60 node (it's a leaf).

Tree Traversals (memorise the order!)

  • Pre-order copies a tree; post-order deletes/evaluates it; in-order sorts a BST

Why Plain BSTs Are Dangerous

  • Balanced tree: h = O(log n) → all operations O(log n)
  • Inserting sorted keys (1, 2, 3, …) builds a chain: h = n−1 → all operations O(n)
  • Worst case: O(n) for search, insert, and delete

AVL Trees — Self-Balancing

  • Named after Adelson-Velsky and Landis (1962)
  • Balance factor: BF(X) = height(right subtree) − height(left subtree)
  • AVL invariant: BF ∈ {−1, 0, +1} for every node
  • Height stays below ~1.44 log₂ n, so every operation is O(log n) worst case

Rotations

y x / \ rotate right / \ x C ---------> A y / \ <--------- / \ A B rotate left B C

A rotation changes shape but keeps the in-order sequence (A, x, B, y, C). Only O(1) links change.

The Four Imbalance Cases (after insert)

CaseWhere new key wentFix
Left-LeftLeft subtree of left childSingle right rotation
Right-RightRight subtree of right childSingle left rotation
Left-RightRight subtree of left childLeft rotation on child, then right rotation
Right-LeftLeft subtree of right childRight rotation on child, then left rotation
Example: Insert 30, 20, 10 → BF(30) = −2 (Left-Left) → one right rotation at 30 makes 20 the root.

5. Binary Heaps 30 marks

This is the other 30-mark topic. You must be able to trace insert (sift-up) and extract-min (sift-down) step by step. Practice by drawing the array after each operation.

Priority Queue ADT

Each element has a priority; highest priority leaves first. Operations: insert, peek/find-min, extract-min.

Applications: CPU/job scheduling, Dijkstra's shortest paths, Prim's MST, event-driven simulation, heapsort, top-k in a stream.

Binary Heap — Two Properties

  1. Shape property: Complete binary tree — every level full except possibly the last, which fills left to right
  2. Heap property: Min-heap: every parent ≤ its children (min at root). Max-heap: every parent ≥ its children (max at root).
A heap is not sorted. Siblings have no ordering between them. Only the parent-child relationship is constrained.

Array Representation — Index Formulas (memorise!)

Parent of i:   ⌊(i − 1) / 2⌋
Left child of i:   2i + 1
Right child of i:   2i + 2

Store nodes level by level; index 0 = root. No pointers needed because the complete shape leaves no gaps.

array: [1, 3, 6, 5, 9, 8] (index 0 = root) 1 / \ 3 6 / \ / 5 9 8

Insert: Sift-Up — O(log n)

  1. Add the new element at the end of the array (maintains shape)
  2. Compare with parent; if smaller, swap (sift up)
  3. Repeat until parent ≤ element (or reach root)

At most one swap per level: O(log n) worst case.

Insert walkthrough (insert 2 into [1, 3, 6, 5, 9, 8])

Place 2 at index 6; parent is index 2 (value 6)
2 < 6: swap → [1, 3, 2, 5, 9, 8, 6]
Now at index 2; parent is index 0 (value 1); 2 > 1: stop
Result: [1, 3, 2, 5, 9, 8, 6]

Extract-Min: Sift-Down — O(log n)

  1. Save the root (it's the minimum)
  2. Move the last element to the root (maintains shape)
  3. Compare with children; swap with the smaller child
  4. Repeat until both children ≥ element (or it's a leaf)

Extract-min walkthrough (from [1, 3, 2, 5, 9, 8, 6])

Remove root 1; move last (6) to root → [6, 3, 2, 5, 9, 8]
Children of index 0: 3 and 2; smaller is 2: swap → [2, 3, 6, 5, 9, 8]
Index 2 has one child (8); 6 < 8: stop
Result: [2, 3, 6, 5, 9, 8]   cost O(log n)

Build-Heap (Bottom-Up, Floyd 1964) — O(n)

  • For i from ⌊n/2⌋ − 1 down to 0: sift-down(i)
  • Leaves are already heaps; most nodes are near the bottom and sift down only a little
  • The sum of all node heights is O(n), so build-heap is O(n)
  • Inserting n keys one at a time is O(n log n) worst case — bottom-up is faster

Heapsort — O(n log n), in-place, not stable

  1. Build a max-heap from the array: O(n)
  2. Repeat n−1 times: swap root with last element, shrink heap by one, sift-down the new root

O(n log n) in every case. Sorts in place (O(1) extra memory). Not stable.

Question 1 (15 marks): Algorithm analysis and arrays [15]

(a) Show that f(n) = 4n² + 10n + 7 is O(n²). State c and n₀. [5]

For n ≥ 1: 4n² + 10n + 7 ≤ 4n² + 10n² + 7n² = 21n².

So choose c = 21, n₀ = 1. For all n ≥ 1: |f(n)| ≤ 21·n² = c·g(n). ✓

Alternatively: c = 21, n₀ = 1. (Any valid c and n₀ with justification is acceptable.)

(b) Time complexity of: for (i=1; i<n; i*=2) for (j=0; j<n; j++) count++; [4]

Outer loop: i doubles each iteration (1, 2, 4, …), so it runs log₂(n) times = O(log n).

Inner loop: runs n times = O(n).

Nested loops multiply: O(n log n).

Justification: total iterations = log₂(n) × n = n·log₂(n).

(c) Why does appending n elements to a dynamic array cost O(n) total? State amortised cost. [6]

With doubling, the copies happen at sizes 1, 2, 4, 8, …, n/2. Total copy work = 1 + 2 + 4 + … + n/2 = n − 1 < n.

Plus n actual writes (one per append). Total = n writes + n copies = O(n).

Amortised cost per append = O(n) / n = O(1) amortised.

One append can cost O(n) (when it triggers a resize/copy), but copies are rare enough that the average is constant.

Question 2 (30 marks): Hashing [30]

(a) Define load factor α. Why resize? What happens during resize? [4]

α = n / m, where n = number of stored entries, m = number of buckets.

When α exceeds a threshold, collisions become frequent and operations slow down. Resizing allocates a bigger table (commonly double), re-inserts every entry (rehashing), which costs O(n) but is O(1) amortised per insert. The new load factor is halved.

(d) What is primary clustering? Why does it occur with linear probing? How does double hashing reduce it? [5]

Primary clustering is when linear probing creates long contiguous runs of occupied slots. These runs grow because any key that hashes into the run must scan through it, and if it lands inside, the run gets even longer.

It occurs because the probe step is always +1: all keys that collide follow the same linear path, so they pile up.

Double hashing uses h(k, i) = (h₁(k) + i·h₂(k)) mod m. The step size h₂(k) depends on the key, so different keys take different paths through the table, reducing the formation of large clusters.

(e) Expected unsuccessful-search probes for α = 0.5 and α = 0.9. Recommend max load factor. [5]

Formula: ½(1 + 1/(1 − α)²)

α = 0.5: ½(1 + 1/(0.5)²) = ½(1 + 4) = ½(5) = 2.5 probes

α = 0.9: ½(1 + 1/(0.1)²) = ½(1 + 100) = ½(101) = 50.5 probes

Recommendation: Keep α ≤ 0.75 (at α = 0.75, unsuccessful search ≈ 8.5 probes, which is acceptable). Above 0.75, probe counts grow rapidly toward the α = 0.9 case of 50.5.

(e) Why is bottom-up build-heap O(n) but inserting n keys one at a time O(n log n)? [5]

Bottom-up (Floyd): Sift down from the last internal node (⌊n/2⌋−1) to the root. Most nodes are near the bottom of the tree and have small heights, so they sift down only a little. The total work (sum of all node heights) is O(n).

One-at-a-time insertion: Each insert does a sift-up that can cost O(log n). Over n inserts: n × O(log n) = O(n log n).

The key difference: bottom-up exploits the fact that most nodes are leaves or near-leaves (height ≤ 1), while one-at-a-time insertion treats every insert as potentially traversing the full height.

(f) Name two applications of priority queues and why a heap suits each. [4]

  1. Dijkstra's shortest path: Repeatedly extracts the vertex with minimum distance. A min-heap gives O(log n) extract-min and O(log n) insert/decrease-key, making the algorithm O((V+E) log V).
  2. CPU/job scheduling: The highest-priority job runs next. A heap gives O(1) peek at the top priority and O(log n) to insert a new job or extract the next one — efficient for a dynamic set of jobs.

(Other valid answers: Prim's MST, event-driven simulation, top-k in a stream, heapsort.)

(b) Write reverse(head). State time complexity. [4]

function reverse(head) {
  let prev = null;
  let curr = head;
  while (curr !== null) {
    let next = curr.next;   // save next node
    curr.next = prev;       // reverse the link
    prev = curr;            // advance prev
    curr = next;            // advance curr
  }
  return prev;             // new head (old tail)
}

Time complexity: O(n) — one pass through the list, O(1) work per node. Space: O(1) — only three pointers.

Worst-case height = n − 1 (a degenerate chain / linked list).

Example: insert keys in sorted order: 1, 2, 3, 4, …, n. Each key goes to the right of the previous, producing a chain of height n−1. All operations become O(n).

(AVL trees prevent this by keeping |BF| ≤ 1, guaranteeing height O(log n).)

Traversal Orders (BST)

  • In-order (L,N,R): visits in sorted order
  • Pre-order (N,L,R): copies a tree
  • Post-order (L,R,N): deletes/evaluates a tree
  • Level-order: BFS, level by level

AVL Rotation Cases

  • Left-Left → single right rotation
  • Right-Right → single left rotation
  • Left-Right → left on child, then right
  • Right-Left → right on child, then left

Key Facts

  • Dynamic array append: O(1) amortised (geometric growth)
  • Hash table: O(1) average, O(n) worst (all collide)
  • BST worst case: O(n) — sorted insertion creates a chain
  • AVL height bound: ~1.44 log₂ n
  • Heap insert/extract-min: O(log n); find-min: O(1); build-heap: O(n)
  • Heapsort: O(n log n), in-place, not stable
  • h₂(k) must never be 0 in double hashing (else infinite loop on one bucket)
  • Tombstones needed for deletion in open addressing (keep probe sequences intact)
